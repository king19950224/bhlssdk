# BoltPreload — 螺栓预紧力超声测量

用超声波量螺栓的回波渡越时间，反算这颗螺栓当前被拧到多紧。设备侧接厂家 FxSDK 1.6（C# 源码编入，`bhls1.6/sdk16`）。

产品线只有两个软件（2026-08-28 定型）。此前的在线监测平台（ASP.NET API + PostgreSQL + Vue 控制台）与 Avalonia 工位软件试验线已整体废弃并从仓库移除。

## 两个软件

### 1. FxMonitor（现场桌面软件，运维/安装用）

`src/FxMonitor` — WinForms 程序：连上设备看实时波形/夹紧力/声时差。标定文件 `.ucf` 只有两处进：给整段法兰配在「现场配置」的法兰表里，
给某一路单独配在右侧「计算参数」页「浏览」；都写进 `farm.json`，没有会话级的临时加载（改了就是改了，重启还在，大屏同一份）。
「参数下发…」按通道段批量写可在线改的参数（探头频率/回波窗/回波宽度/增益/脉冲组），写完逐项读回核对；单路的六项在右侧「硬件调节」页直接改。
「找回波窗」对选中的通道做全波扫描（厂家"扫波"），
在整段波形上点回波起始位置，程序取起点前 2 us、按 1 us 取整写成回波窗。改参数后什么时候置零由操作员定，程序不弹窗催、不在列表上标（和厂家软件一致）。
工具栏上只剩只影响本窗口显示的「显示平均」（最近 N 帧平均，数字末位一直闪就调大）；温度补偿和温度平滑挪进了右侧「计算参数」页（厂家放在那）。

**右侧三页和厂家同名同项，框里始终有数、不留空**：
- 「硬件调节」：正向脉冲 / 反向脉冲 / 占空比 / 增益 / 探头频率 / 回波宽度 六个可直接改的数字框，显示设备上这一路现在的值，改了哪几项「应用」只写那几项、写完读回核对；
  底下一行只读显示回波窗、参考声时、参考温度、阈值。多路一起改仍走「参数下发…」表格。
- 「计算参数」：温度通道（0 = 本路，填别的通道号 = 借那一路的温度，存 farm.json `tempFrom`）、温度平滑档位（全局）、温度补偿三选一（不使用 / 材料系数 / 自定义系数，全局）、
  结果计算三选一（材料系数 = 按试件规格算理论斜率；标定文件 = 用 .ucf；载荷标定是厂家试验模式，做完拿 .ucf 到这里选）+ 当前标定文件名和「浏览」——选中的 .ucf 拷到程序目录并绑到这一路
  （通道有自己的规格就绑规格，否则绑所属法兰）。页签上方一行小结：通道 · 温度补偿 · 结果计算，和厂家一样。
- 材料等级的常数（屈服 / 声速 / 弹模 / 声弹因子 / 温度系数）在「试件规格」页「材料规格 ?」打开的材料库里改；温度系数没单独填的显示 SDK 默认 0.00010269，不留空。

**界面照厂家工位软件排**：六个卡片按厂家顶栏顺序（夹紧力 / 温度 / 回波声时 / 伸长量 / 声时差 / 标准差）；波形横轴默认按长度 mm 画（长度 = 声时×声速/2，声速取这一路试件材料，可切回 ns），
图上画 SDK 判出的主回波区（绿带）、极值/前沿标记（+）、检出点（虚线），鼠标悬停显示该点长度/声时/幅值，右下角 SNR/DL 用 SDK 同一算法算这一帧。
波形下面一排：通道号、「测量模式」下拉（自动/位置/阈值，改的是设备存储区参数，要已置零的通道）、◀ ▶ 切上一路/下一路、「停止/继续」（设备待机，数字停住）、「测回」。
**「测回」**把当前这一路此刻显示的读数记成一行进底部**「手动测量结果」**表（采集时间、通道、试件、分组、温度、回波声时、声时差、伸长量、夹紧力、标准差、备注），
表可按试件和时间段筛、双击备注填工况（如加载级 500 / 1000）、删行、「导出…」成 CSV（UTF-8 带 BOM，Excel 直接开）。数据存 exe 旁 `data\手动测量结果.csv`，发布脚本不清 `data\`，重发不丢。
分级加载试验就是：每加一级点一次「测回」，备注里写级数，做完导出。

**和大屏用同一份 `farm.json`**（把大屏 `wwwroot/farm.json` 复制到 exe 旁）：按地址栏里的 IP 在 `devices[]` 里找到"我连的是哪台"，
用它那台的接线/标定/额定/口径，列表多一列"位置"（塔筒顶段法兰 #24），置零对话框和操作记录里也写位置，现场知道拧的是哪颗；
同一颗螺栓桌面端和大屏算出来是同一个数。地址对不上任何设备、或没有 `farm.json` 时退回老行为：程序目录最新的 `.ucf` 对全部通道生效、
按自由置零口径显示 `k×Δt+b`，标签上会说明。

**「现场配置…」**：不用手改 `farm.json`。连上设备后，扫到的通道（有没有信号、置没置零、信噪比）列成表，逐路选"接在哪个法兰"、填螺栓号
（不清楚可先空着）；每个法兰选标定文件（下拉列出程序目录和大屏目录里的 `.ucf`，选中即显示斜率）、填额定预紧力；法兰的名字/螺栓数/正上方编号/顺逆时针也在这改。
保存前校验（机组号撞车、螺栓号超范围/重复、标定文件找不到、一路探头都没接……），过了才写：写 exe 旁的 `farm.json`；本机跑着大屏就自动找到它的目录，
同时写进 `wwwroot/farm.json`、把用到的 `.ucf` 拷到大屏 exe 旁——大屏保存即重载。大屏在别的机器上就"另存为"拷过去。
文件里不认识的字段（`kind`、`marks`、`plannedChannels`、别的设备……）原样保留；老写法的文件读得进来，保存时转成 `devices[]` 新写法。
一次只配"当前连着的这台设备"：改它的机组号/地址都认得是同一台（不会多出一条）；地址撞上别的设备、机组号撞车都拦；删法兰模板时别的设备接线里的 `index` 跟着重排，
别的设备还在用的模板不让删。改了机组号，历史库里老机组号下的数据不会跟着搬（那是另一台机组的历史了）。

**右侧「试件规格」页**和厂家同一页同样七项：名称（唯一）、近似总长、材料规格（? 看/改这一等级的常数）、有效长度（? 按夹持长度 + 连接方式算）、
净截面积（? 按公称直径 + 螺距算 As）、分组（= 法兰，? 打开现场配置）、下限/上限。选中哪一路显示哪一路，一路一个试件，「保存」写进 `farm.json`（`channelSpecs`），大屏读同一份。
近似总长照厂家的用法直接决定回波窗：保存时总长变了、设备连着，就按 总长×2×10⁶/声速 向下取整到 1 µs 写进这一路（和厂家算出来的值一致，如 240 mm → 81000 ns）。
材料等级的常数在「材料规格 ?」打开的材料库里（`materials[]`）。法兰级默认规格和规格库只在「现场配置…」里管（给整段法兰一次配齐用），试件页上没有。
有 `.ucf` 时力值用文件斜率，规格只作对照和放回波窗；没有 `.ucf` 才用规格的理论斜率（界面标"理论"）。规格说回波该在窗外、设备窗口却没跟上的，列表标"回波窗不符"。

**没有标定文件也没有试件规格就不显示夹紧力**（只显示声时差）——软件里没有任何"默认斜率"，没有出处的数不上界面。
列表的"状态"列和大屏同一份判定（`FxDevice.Health.Judge`：基线失配 → 探头无信号 → 检测异常 → 未标定 → 基线可疑 → 未配额定 → 松动/偏低/正常），
同一颗螺栓两边不光是同一个数、也是同一个词；桌面端另加注一样：信噪比在探头门以下的"信号弱"。
桌面端和厂家软件一样，只要设备回了帧数字就照常显示（探头无信号、回波窗不符只在状态列和悬停提示里注明，判断交给看波形的人）；大屏面向业主，无信号时用文字顶掉数字。
置零、参数下发/硬件调节应用、标定文件绑定、温度通道、材料库、现场配置保存都记在 exe 旁的 `操作记录.log`。

**「打开大屏」**：在浏览器里打开业主大屏。本机大屏服务没在跑就问一句、以管理员身份启动服务（没装服务就用旁边的「安装大屏服务.cmd」装上），
再开网页——不会再拉起带黑窗口的控制台实例。大屏在别的机器上就在 `settings.json` 里填 `DashboardUrl`。

```powershell
dotnet run --project src/FxMonitor              # 或 FxMonitor.exe [ip:port] [--auto] [--demo]
```

### 2. BoltPreload.Monitor（业主网页大屏）

`src/BoltPreload.Monitor` — 自托管只读监视器：本机 SDK 直连设备，浏览器（局域网任意电脑/手机）开网页就能看，无需登录。历史数据落本地 SQLite（exe 旁 `data/history.db`），标定用 exe 旁的 `.ucf` 文件。

**一个大屏接很多台设备**：每台采集设备装在一台机组上，在 `farm.json` 的 `devices[]` 里各写一项；服务端给每台设备一个独立的采集器（各自连接、保活、巡检、维护模式），共用一个页面广播和一个历史库，历史库所有表都带机组号。总览页每台接了设备的机组各显各的状态，点进去看哪台就是哪台的数据；报警中心和报告跨机组，位置写"F05 · 中段法兰 · CH9"。

**基线口径**（`baseline`）——决定 `k×Δt` 这个数叫什么，必须和现场置零的方式一致：

- `"anchor"` **在役锚定**（默认）：螺栓已经拧紧在法兰上才置零。`k×Δt` 是**较锚定时刻的变化量**（`dkn`，负 = 松了）。绝对预紧力只能按"锚定时 = 额定值"估算：`kn = ratedKn + k×Δt`，页面标"估算"；没配额定值就只显示变化量、不判偏低/松动。
- `"free"` **自由状态置零**：拧紧前记基线，`kn = k×Δt + b` 就是绝对预紧力。安装期或实验室才做得到。

数据口径：

- **没有 `.ucf` 就不算预紧力**：历史里 `kn`/`dkn` 为空、状态记"未标定"，页面只显示声时差并提示放标定文件。声时差 `dt` 永远原样保存，任何时候都能用新标定重算。
- 标定文件是厂家软件做载荷标定得到的，**对应一种螺栓规格（直径 × 夹持长度）**；哪台设备的哪个法兰用哪份写在 `devices[].flanges[].ucf`。
  `.ucf` 里只有拟合后的 64 个点（Δt ns → kN）和单位，**不含螺栓规格**，文件是给哪种螺栓做的只能靠文件名和做文件的人；
  斜率错一份，力值就错几倍。现场文件放在 `src/BoltPreload.Monitor/` 下随 exe 输出（桌面端链接同一份），目前：
  `标定文件-M64-180加持.ucf` = M64 螺栓、夹持长度 180 mm，2.3281 kN/ns，标到 1659 kN（2026-04-09 厂家提供）；
  配套额定 1780 kN 的出处是《螺栓预紧力依据说明》（M64×210 10.9 级，A_s 2676 mm²，Rp0.2 940 MPa → 屈服 2515 kN 的 70%）。
  法兰点名了 `.ucf` 却读不到，按未标定，不会改用目录里别的最新文件。没有额定值就填 `0`，不要填另一种螺栓的额定让松动报警失效。
- **螺栓状态只在服务端判一次**（`Health.Judge`：在位识别 → 基线失配 → 检测异常 → 未标定 → 基线可疑 → 未配额定 → 松动/偏低/正常），帧、历史采样、事件、页面显示全用同一个结论，业主看到的和报表里写的对得上。
- **有标定、没额定值 = "未配额定"**（`unrated`），不是"正常"：只显示较锚定的变化量 ΔkN，不判偏低/松动，报告里单独计数、不进健康率（健康率分母只含正常/偏低/松动）。"正常"是和阈值比过之后才有的结论。
- **力值为负或超出额定 130% = 基线可疑**（`badbase`）：预紧力物理上不为负、也不会比设计值高三成，出现即基线/参数/额定值有问题——
  典型是改了回波窗、阈值、测量模式没重新置零（检出的回波声时随之挪动，旧基线作废）。记为需要重新置零的运维问题，不报成"松动报警"也不算"正常"。
- **声时差是每个客户端自己算的**（SDK 在客户端用会话里缓存的参考声时、测量模式、阈值从原始波形算），设备只发波形。所以桌面端在设备上置零/改参数，
  大屏的会话不会自动知道。三道保险：① 桌面端置零/下发参数后 `POST /api/resync` 通知大屏（局域网内可调，只触发重读，并重读 `anchors.json`），几秒内追平；
  ② 大屏自己盯声时差——相邻两帧跳变超过 50 ns 就当"有人动了基线/参数"，停该路落库、立刻重读；③ 每 10 分钟巡检时全体重读兜底。
  重读到参考声时变了记"基线重置"事件。不是本会话轮询的通道的帧（另一个客户端在扫描）直接丢掉，不判在位、不落库。
- **改参数不强制重新置零（和厂家软件一致）**：回波窗/回波宽度/阈值/测量模式/脉冲/探头频率/增益改完就完，SDK 自己会在这些参数变化后重新捕获自动法锚点，
  要不要重新置零由操作员按波形判断。桌面端只做两件事：写完读回核对、通知大屏重读基线。大屏这边在估算值出格（负值或超额定 130%）时判"基线可疑"，在范围内的偏移查不出来——
  现场改了参数该置零的还是要置零。
- 每次启动生效的标定（文件名、k、b、点数、额定）和口径按法兰记入 `cal_log` 表，历史里每个力值都能对回当时的系数与口径。
- **自动法（测量模式 0）的置零锚点存在 exe 旁 `data\anchors.json`**：设备存储区只存参考声时/温度/波形，包络锚点和载波周期存不下，厂家软件写在项目文件里，我们写在这。
  桌面端置零成功时按（设备 IP、通道、参考声时）记一条；两个程序连接时读它——设备上的参考声时和记的对得上才用，对不上（别的软件重新置零过）就让 SDK 自己重新捕获。
  没有锚点时 SDK 用连接后第一帧重新捕获，螺栓在这期间松紧超过半个周期就可能锁到相邻上升沿，声时差整段错一个周期（约 415～450 ns）。两个程序发布在同一个文件夹时就是同一份。
- **基线流水** `zero_log`：每次连接/补读都把各路参考声时和上次记的比，变了就是现场重新置零过——记流水、写一条"基线重置"事件（参考声时 A → B），趋势图上画竖线标出，力值这一跳有出处。`/api/archive` 给出各路当前基线和重置次数。
- 采样每 5 秒一条保留 90 天；事件（状态变化/报警）保留 2 年。写入 `synchronous=FULL`，断电不丢已提交的数据。
- 落盘走独立写线程，页面查询各开连接；队列丢帧和写入失败会计数并在页面底部显示，不静默。
- **本期说明**：报警中心和统计报告各有一段话，按固定句式写当前颗数、要点名的螺栓，以及这段时间新出现的松动、恢复和读数基准更新。数字沿用已经算好的状态和力值，不另算、不外发。

```powershell
dotnet run --project src/BoltPreload.Monitor    # 默认 http://0.0.0.0:5080
```

**桌面端和大屏别同时连一台设备**。09-10 实测串口服务器其实接受多路 TCP、并把仪器的回包发给每一路：两边同时连着也都能收到数据，
但一边的命令回包会串到另一边（大屏日志里冒出它没轮询的 CH14/CH17），写参数时更可能互相打断。现场要用桌面端置零/调参时，在大屏主机上让那台机组进入**维护模式**：
打开那台机组的法兰页 → 运维详情里点"现场维护 30 分钟 / 2 小时"（或本机 `POST /api/maintenance {"turbine":5,"minutes":30}`），大屏断开这台设备并在期限内不重连，其余机组照常监测，页面显示"维护中"而不是"未连接"；
到期自动恢复，也可点"结束维护"立即恢复。别再靠杀进程让路。

大屏怎么知道某一路被置零了：参考声时只在连接时和定时补读时从设备读。缺参考声时的测点，没探头信号的按 10 分钟起步、翻倍到 1 小时补读一次；
**有探头信号的两分钟补读一次**（刚装上、正在置零的就是这种），桌面端置零后大屏两分钟内接上；结束维护重连时也会全部重读。

配置在 `wwwroot/farm.json`。`flanges[]` 是**全场统一的法兰结构模板**，`devices[]` 是**每台设备的接线**。
平时用桌面端的「现场配置…」改它（见上），下面的字段表是文件格式的说明，手改也认。
**改完保存即生效，不用重启**：服务监视这个文件，保存后 1.5 秒内重新解析——解析不过（JSON 写错、一台设备都没有）就拒绝、原配置照常跑，
控制台写明哪里错；解析过了老的采集器退役断开、按新配置重连（几秒钟），历史库登记新的标定/额定，所有打开的页面自动刷新。
也可在法兰页"运维详情"里点"重新加载配置"（或本机 `POST /api/reload`）立刻应用。
**启动时读不到它（文件不在、写坏了、发布脚本正在换文件）不按任何默认设备跑**：只提供网页（所有机组"未接入"），每 10 秒重试一次，文件出现/修好就自动接上——
按虚构的接线去测、去落库、去报警，比不监测更糟。`devices` 写成空数组同样一台都不接，不会退到老写法的默认 IP。字段：

| 字段 | 含义 |
|---|---|
| `farmName` / `turbineCount` | 风场名、机组数（总览画多少台） |
| `baseline` | 基线口径，`"anchor"`（在役锚定，默认）或 `"free"`（自由状态置零），见上文"基线口径"。全场统一 |
| `tcMode` / `tempCoefficient` | 声时差温度补偿，和厂家 iFastApp 同一套：`0` 不使用（Δt = 回波声时 − 参考声时）、`1` 材料系数（默认，SDK 碳钢 0.00010269）、`2` 自定义系数（系数写 `tempCoefficient`，厂家项目常见 0.000101）。桌面端在右侧「计算参数」页改 |
| `tempTau` | 探头温度平滑档位：`"direct"` 不平滑 / `"fast"` 60 s（默认，厂家软件的档位）/ `"balanced"` 180 s（SDK 缺省）/ `"stable"` 480 s / `"conservative"` 900 s。界面显示用平滑温度；算声时差用原始温度（和置零写下的参考温度同一种数）。原始温度超出 SDK 有效范围（Pt1000 开路）时改用平滑温度，避免力值飞掉 |
| `devices[].tempFrom` | 温度借用 `{ "通道": 借哪一路 }`，如 `{ "3": 1 }` = CH3 温补用 CH1 的温度。探头没温感或 Pt1000 坏了才用；被借的那一路也要在接线表里。桌面端只在「计算参数」页的温度通道里改它（现场配置的接线表不再有这一列，保存时原样保留、只清掉已不在接线里的通道） |
| `thresholds.ratedKn / warnRatio / alarmRatio` | 全局额定预紧力与偏低/松动判定比例；设备接线里给了法兰自己的 `ratedKn` 时以那个为准。额定值要有出处（主机厂紧固工艺/设计预紧力），没有就填 `0`——状态记"未配额定"、只显示变化量，别填一个猜的数让页面报假松动 |
| `flanges[].name / boltCount` | 法兰名、螺栓总数（全部画出） |
| `flanges[].plannedChannels` | 该法兰的规划探头位（含未接的），页面按它固定显示位子，没接的标"待接入"（叶根法兰预设 12 位） |
| `flanges[].numbering` | `{ topBolt, clockwise }`：图纸上正上方那颗的编号、编号方向，用来和图纸对号 |
| `flanges[].kind` | `"root"` 表示叶根（画成层合板筒 + 变桨轴承），不写按塔筒钢法兰画 |
| `flanges[].marks` | 可选，`[{ at: 螺栓号, label }]`，在环外标基准位置 |
| `devices[].turbine` | 这台设备装在哪台机组（一台机组只能接一台） |
| `devices[].device` | 设备 `ip:port`，服务端自动连接、断线重连 |
| `devices[].flanges[].index`（或 `name`） | 对到模板里的哪个法兰 |
| `devices[].flanges[].channels` | **该法兰上实际接了探头、置过零的通道**——这就是接线表。一台 48 路设备可以跨多个法兰（顶段 CH1–8、中段 CH9–16……）；服务端只轮询这些通道 |
| `devices[].flanges[].channelBolts` | `{ "通道": 螺栓号 }`，每个探头实际装在哪颗螺栓上；没配的在图上从 #1 起均匀占位，但牌子上不写螺栓号（示意位置不能冒充接线记录） |
| `devices[].flanges[].ucf` | 该法兰螺栓规格对应的标定文件名（程序目录下）。没写文件名时才回落到程序目录里最新的 `.ucf`；写了名字却读不到，按未标定，不会拿别的文件顶替 |
| `devices[].flanges[].ratedKn` | 该法兰的额定预紧力 kN，覆盖全局 `thresholds.ratedKn`；没写时用法兰默认规格的 `ratedKn` |
| `materials[]` | 材料库：`grade` → `yieldMpa` / `velocity` / `elasticGpa` / `acoustic`（声弹因子）/ `tempCoefficient`。没写的等级用内置默认（8.8/9.8/10.9/12.9，5900 m/s，206 GPa，声弹因子 2） |
| `boltSpecs[]` | 规格库（厂家「试件规格」）：`name` 唯一；`nominalMm` / `pitchMm` → 净截面积 As（ISO 898-1，`areaMm2` 可覆盖）；`grade`；`lengthMm` 近似总长 → 回波窗；`clampMm` 夹持长度 + `joint`（`boltNut` 夹持+0.9d / `stud` +0.8d / `tapped` +1.0d）→ 有效长度（`effectiveMm` 可覆盖）；`ratedKn`、`lowerKn` / `upperKn`、`ucf`（这种螺栓的标定文件） |
| `devices[].flanges[].boltSpec` | 法兰默认规格名。法兰没写 `ucf` 时用规格的 `ucf`，再没有就按规格算理论斜率（Points=0 标"理论"） |
| `devices[].flanges[].channelSpecs` | `{ "通道": 规格名 }`：这一路装的不是法兰默认那种螺栓。只认那条规格自己的标定/理论/额定，不沾法兰的 `.ucf`——法兰的文件是给另一种螺栓做的 |
| `devices[].flanges[].plannedChannels` | 可选，覆盖模板里该法兰的规划位 |
| `devices[].guardChannels` | 巡检位：只轮询、只判有没有探头，抓插到规划外通道的探头 |

写了 `channels` 或 `channelBolts` 的法兰才算接在这台设备上；只有模板规划位的法兰是"规划"，页面画待接入的位子。一路通道只能属于一个法兰，重复写时按先出现的算并在启动日志里警告。
老写法（顶层 `device` + `bind` + `flanges[].channels`）仍然认，当作只有一台设备；老历史库启动时自动升级（已有数据归老写法里的那台机组）。

**接线怎么核对**：探头没有身份，哪颗螺栓接了几号通道只有装的人知道，`channels` + `channelBolts` 就是接线表。装完验证：把某颗螺栓的探头脱耦或拔下，页面上对应通道的卡片、法兰图上的牌子会白框闪 20 秒，提示条写"接线核对：CHx（xx法兰）3 秒前探头信号消失"——亮的是几号，那颗螺栓就是几号。有探头信号却不在任何法兰接线表里的通道，提示条会点名"未分配"。

页面路由：`#/farm` 总览、`#/turbine/N` 任一机组、`#/flange/i` 当前机组任一法兰（没接入的也能看画面，只是没数据）、`#/alarms`、`#/report`。

**页面文案的规矩**：业主视图只有状态词（正常/偏低/松动/无信号/未置零/待接入……）和数字，不写句子、不出现配置文件名和运维术语；
为什么、该怎么办放在悬停提示（title）里，标定文件名/斜率/库容量/服务日志只在法兰页的"运维详情"视图露出来。

机组结构页是 Three.js 三维场景（`wwwroot/tower3d.js`，库文件 vendored 在 `wwwroot/vendor/three`，MIT，随 exe 一起发布，不依赖外网）；浏览器没有 WebGL 时自动退回 SVG 版。

## 发布与部署

```powershell
.\publish.ps1                      # → dist\螺栓预紧力监测\（固定输出目录），整个文件夹拷走
.\publish.ps1 -Out D:\发布\xxx      # 要发到别处才带 -Out
```

发布前把目标目录里开着的 `FxMonitor.exe` 关掉（脚本会先检查，不会删半截）。目录里的 `wwwroot\farm.json`、`.ucf`、`data\`、`logs\`、`settings.json`、`操作记录.log` 每次发布都保留。

一个文件夹装下全部：`FxMonitor.exe`、`BoltPreload.Monitor.exe`（都是自包含单文件，目标机不用装 .NET）、`wwwroot\`（页面 + `farm.json`）、
标定文件 `.ucf`、`安装大屏服务.cmd`、`卸载大屏服务.cmd`。两个程序在同一个文件夹里共用 `wwwroot\farm.json` 和 `.ucf`——桌面端旁边没有 `farm.json` 时读 `wwwroot\farm.json`，
现场配置对话框也只写这一份；两个程序不合成一个进程：大屏是业主机上 24 小时跑的服务，桌面端是运维偶尔开的工具，合在一起谁手一滑关了窗口大屏就黑。

**业主电脑：大屏装成 Windows 服务**。整个文件夹拷过去，右键「安装大屏服务.cmd」以管理员身份运行一次：服务 `BoltPreloadMonitor`（显示名"螺栓预紧力大屏服务"），
开机自起、不用登录、**没有任何窗口**，意外退出由系统 5/10/30 秒后自动重启（实测杀掉进程 12 秒内恢复），顺带放行防火墙 5080 端口。
重装时先停旧服务、等进程真退完、等服务项真删掉再装新的（不是固定等 3 秒），不会出现新实例抢不到端口"刚装好就意外终止一次"。
「卸载大屏服务.cmd」停止并删除服务，历史库和日志不动。
双击 `BoltPreload.Monitor.exe` 是控制台模式（调试用，业主机上不要这么跑），窗口顶部会写明本机/局域网网址和"别关这个窗口"。
不论哪种方式，每一行日志都写进 exe 旁 `logs\monitor-yyyyMMdd.log`（保留 30 天）：设备连接为什么断（对端关闭/网络中断/心跳超时）、什么时候重载过配置、
服务什么时候被停（"正在停止服务 … 服务已停止"，没有这两行就是被杀或崩了）都查得到。停服务先让保活循环退出再断设备，1–2 秒停完；
收尾超过 20 秒宿主会报超时，进程记一行日志正常退出，不再以崩溃收场。
现场调试：`FxMonitor.exe` 连设备置零/调参/现场配置，「打开大屏」按钮开网页；装了服务但服务没在跑时它会提示去启动服务，不会另起一个控制台实例抢端口。

配置重载时维护状态会带到新一代：现场正在维护模式下用桌面端置零、顺手保存了现场配置，大屏不会因为重载就把设备抢回去。
