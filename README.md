# BoltPreload — 螺栓预紧力超声测量

用超声波量螺栓的回波渡越时间，反算这颗螺栓当前被拧到多紧。设备侧接厂家 FxSDK 1.6（C# 源码编入，`bhls1.6/sdk16`）。

产品线只有两个软件（2026-08-28 定型）。此前的在线监测平台（ASP.NET API + PostgreSQL + Vue 控制台）与 Avalonia 工位软件试验线已整体废弃并从仓库移除。

## 两个软件

### 1. FxMonitor（现场桌面软件，运维/安装用）

`src/FxMonitor` — WinForms 程序：连上设备看实时波形/夹紧力/声时差，加载 `.ucf` 标定文件（exe 旁有就自动加载）；
「参数下发…」按通道段批量写可在线改的参数（探头频率/回波窗/回波宽度/增益/脉冲组），写完逐项读回核对。

**和大屏用同一份 `farm.json`**（把大屏 `wwwroot/farm.json` 复制到 exe 旁）：按地址栏里的 IP 在 `devices[]` 里找到"我连的是哪台"，
用它那台的接线/标定/额定/口径，列表多一列"位置"（塔筒顶段法兰 #24），置零对话框和操作记录里也写位置，现场知道拧的是哪颗；
同一颗螺栓桌面端和大屏算出来是同一个数。地址对不上任何设备、或没有 `farm.json` 时退回老行为：程序目录最新的 `.ucf` 对全部通道生效、
按自由置零口径显示 `k×Δt+b`，标签上会说明。

**没有加载标定文件就不显示夹紧力**（只显示声时差）——软件里没有任何"默认斜率"，没有出处的数不上界面。
置零、参数下发、加载标定文件都记在 exe 旁的 `操作记录.log`。

```powershell
dotnet run --project src/FxMonitor              # 或 FxMonitor.exe [ip:port] [--auto] [--demo]
dotnet publish src/FxMonitor -c Release         # 自包含单文件 exe，拷走就能跑
```

### 2. BoltPreload.Monitor（业主网页大屏）

`src/BoltPreload.Monitor` — 自托管只读监视器：本机 SDK 直连设备，浏览器（局域网任意电脑/手机）开网页就能看，无需登录。历史数据落本地 SQLite（exe 旁 `data/history.db`），标定用 exe 旁的 `.ucf` 文件。

**一个大屏接很多台设备**：每台采集设备装在一台机组上，在 `farm.json` 的 `devices[]` 里各写一项；服务端给每台设备一个独立的采集器（各自连接、保活、巡检、维护模式），共用一个页面广播和一个历史库，历史库所有表都带机组号。总览页每台接了设备的机组各显各的状态，点进去看哪台就是哪台的数据；报警中心和报告跨机组，位置写"F05 · 中段法兰 · CH9"。

**基线口径**（`baseline`）——决定 `k×Δt` 这个数叫什么，必须和现场置零的方式一致：

- `"anchor"` **在役锚定**（默认）：螺栓已经拧紧在法兰上才置零。`k×Δt` 是**较锚定时刻的变化量**（`dkn`，负 = 松了）。绝对预紧力只能按"锚定时 = 额定值"估算：`kn = ratedKn + k×Δt`，页面标"估算"；没配额定值就只显示变化量、不判偏低/松动。
- `"free"` **自由状态置零**：拧紧前记基线，`kn = k×Δt + b` 就是绝对预紧力。安装期或实验室才做得到。

数据口径：

- **没有 `.ucf` 就不算预紧力**：历史里 `kn`/`dkn` 为空、状态记"未标定"，页面只显示声时差并提示放标定文件。声时差 `dt` 永远原样保存，任何时候都能用新标定重算。
- 标定文件是厂家软件做载荷标定得到的，**对应一种螺栓规格（直径 × 夹持长度）**；哪台设备的哪个法兰用哪份写在 `devices[].flanges[].ucf`。
  `.ucf` 里只有拟合后的 64 个点（Δt ns → kN）和单位，**不含螺栓规格**，文件是给哪种螺栓做的只能靠文件名和做文件的人；
  斜率错一份，力值就错几倍。现场文件放在 `src/BoltPreload.Monitor/` 下随 exe 输出（桌面端链接同一份），目前：
  `标定文件-M64-180加持.ucf` = M64 螺栓、夹持长度 180 mm，2.3281 kN/ns，标到 1659 kN（2026-04-09 厂家提供）；
  配套额定 1780 kN 的出处是《螺栓预紧力依据说明》（M64×210 10.9 级，A_s 2676 mm²，Rp0.2 940 MPa → 屈服 2515 kN 的 70%）。
- **螺栓状态只在服务端判一次**（`Health.Judge`：在位识别 → 基线失配 → 检测异常 → 未标定 → 基线可疑 → 未配额定 → 松动/偏低/正常），帧、历史采样、事件、页面显示全用同一个结论，业主看到的和报表里写的对得上。
- **有标定、没额定值 = "未配额定"**（`unrated`），不是"正常"：只显示较锚定的变化量 ΔkN，不判偏低/松动，报告里单独计数、不进健康率。"正常"是和阈值比过之后才有的结论。
- **力值为负 = 基线可疑**（`badbase`）：预紧力物理上不为负，锚定口径下为负即"较锚定丢了超过 100% 额定"，只可能是基线或额定值错了——记为需要重新置零的运维问题，不报成"松动报警"。
- 每次启动生效的标定（文件名、k、b、点数、额定）和口径按法兰记入 `cal_log` 表，历史里每个力值都能对回当时的系数与口径。
- **基线流水** `zero_log`：每次连接/补读都把各路参考声时和上次记的比，变了就是现场重新置零过——记流水、写一条"基线重置"事件（参考声时 A → B），趋势图上画竖线标出，力值这一跳有出处。`/api/archive` 给出各路当前基线和重置次数。
- 采样每 5 秒一条保留 90 天；事件（状态变化/报警）保留 2 年。写入 `synchronous=FULL`，断电不丢已提交的数据。
- 落盘走独立写线程，页面查询各开连接；队列丢帧和写入失败会计数并在页面底部显示，不静默。

```powershell
dotnet run --project src/BoltPreload.Monitor    # 默认 http://0.0.0.0:5080
```

**桌面端和大屏别同时连一台设备**。09-10 实测串口服务器其实接受多路 TCP、并把仪器的回包发给每一路：两边同时连着也都能收到数据，
但一边的命令回包会串到另一边（大屏日志里冒出它没轮询的 CH14/CH17），写参数时更可能互相打断。现场要用桌面端置零/调参时，在大屏主机上让那台机组进入**维护模式**：
打开那台机组的法兰页 → 运维详情里点"现场维护 30 分钟 / 2 小时"（或本机 `POST /api/maintenance {"turbine":5,"minutes":30}`），大屏断开这台设备并在期限内不重连，其余机组照常监测，页面显示"维护中"而不是"未连接"；
到期自动恢复，也可点"结束维护"立即恢复。别再靠杀进程让路。

大屏怎么知道某一路被置零了：参考声时只在连接时和定时补读时从设备读。缺参考声时的测点，没探头信号的按 10 分钟起步、翻倍到 1 小时补读一次；
**有探头信号的两分钟补读一次**（刚装上、正在置零的就是这种），桌面端置零后大屏两分钟内接上；结束维护重连时也会全部重读。

配置在 `wwwroot/farm.json`。`flanges[]` 是**全场统一的法兰结构模板**，`devices[]` 是**每台设备的接线**；改设备/接线/标定/阈值要重启服务，只改画图相关的字段刷新页面即可：

| 字段 | 含义 |
|---|---|
| `farmName` / `turbineCount` | 风场名、机组数（总览画多少台） |
| `baseline` | 基线口径，`"anchor"`（在役锚定，默认）或 `"free"`（自由状态置零），见上文"基线口径"。全场统一 |
| `thresholds.ratedKn / warnRatio / alarmRatio` | 全局额定预紧力与偏低/松动判定比例；设备接线里给了法兰自己的 `ratedKn` 时以那个为准。额定值要有出处（主机厂紧固工艺/设计预紧力），没有就填 `0`——状态记"未配额定"、只显示变化量，别填一个猜的数让页面报假松动 |
| `flanges[].name / boltCount` | 法兰名、螺栓总数（全部画出） |
| `flanges[].plannedChannels` | 该法兰的规划探头位（含未接的），页面按它固定显示位子，没接的标"待接入"（叶根法兰预设 12 位） |
| `flanges[].numbering` | `{ topBolt, clockwise }`：图纸上正上方那颗的编号、编号方向，用来和图纸对号 |
| `flanges[].kind` | `"root"` 表示叶根（画成层合板筒 + 变桨轴承），不写按塔筒钢法兰画 |
| `flanges[].marks` | 可选，`[{ at: 螺栓号, label }]`，在环外标基准位置 |
| `devices[].turbine` | 这台设备装在哪台机组（一台机组只能接一台） |
| `devices[].device` | 设备 `ip:port`，服务端自动连接、断线重连 |
| `devices[].flanges[].index`（或 `name`） | 对到模板里的哪个法兰 |
| `devices[].flanges[].channels` | **该法兰上实际接了探头、置过零的通道**——这就是接线表。一台 48 路设备可以跨多个法兰（顶段 CH1–8、中段 CH9–16……）；服务端只轮询这些通道 |
| `devices[].flanges[].channelBolts` | `{ "通道": 螺栓号 }`，每个探头实际装在哪颗螺栓上；没配的在图上从 #1 起均匀占位，但牌子上不写螺栓号（示意位置不能冒充接线记录） |
| `devices[].flanges[].ucf` | 该法兰螺栓规格对应的标定文件名（程序目录下）；没写的回落到程序目录里最新的 `.ucf` |
| `devices[].flanges[].ratedKn` | 该法兰的额定预紧力 kN，覆盖全局 `thresholds.ratedKn` |
| `devices[].flanges[].plannedChannels` | 可选，覆盖模板里该法兰的规划位 |
| `devices[].guardChannels` | 巡检位：只轮询、只判有没有探头，抓插到规划外通道的探头 |

写了 `channels` 或 `channelBolts` 的法兰才算接在这台设备上；只有模板规划位的法兰是"规划"，页面画待接入的位子。一路通道只能属于一个法兰，重复写时按先出现的算并在启动日志里警告。
老写法（顶层 `device` + `bind` + `flanges[].channels`）仍然认，当作只有一台设备；老历史库启动时自动升级（已有数据归老写法里的那台机组）。

**接线怎么核对**：探头没有身份，哪颗螺栓接了几号通道只有装的人知道，`channels` + `channelBolts` 就是接线表。装完验证：把某颗螺栓的探头脱耦或拔下，页面上对应通道的卡片、法兰图上的牌子会白框闪 20 秒，提示条写"接线核对：CHx（xx法兰）3 秒前探头信号消失"——亮的是几号，那颗螺栓就是几号。有探头信号却不在任何法兰接线表里的通道，提示条会点名"未分配"。

页面路由：`#/farm` 总览、`#/turbine/N` 任一机组、`#/flange/i` 当前机组任一法兰（没接入的也能看画面，只是没数据）、`#/alarms`、`#/report`。

**页面文案的规矩**：业主视图只有状态词（正常/偏低/松动/无信号/未置零/待接入……）和数字，不写句子、不出现配置文件名和运维术语；
为什么、该怎么办放在悬停提示（title）里，标定文件名/斜率/库容量/服务日志只在法兰页的"运维详情"视图露出来。

机组结构页是 Three.js 三维场景（`wwwroot/tower3d.js`，库文件 vendored 在 `wwwroot/vendor/three`，MIT，随 exe 一起发布，不依赖外网）；浏览器没有 WebGL 时自动退回 SVG 版。

## 仓库结构

- `src/FxMonitor` — 桌面软件（监视 + 参数下发）
- `src/BoltPreload.Monitor` — 网页大屏
- `src/FxDevice` — 两者共用的设备连接引擎（协议分组、写后读回判定都在这里）
- `bhls1.6/` — 厂家 C# SDK 1.6 源码
- `bhls1.6/FxReader` — 厂家示例 CLI（抓 raw / 打零点），不进主方案、不随现场发布
- `资料/工程文档/` — 历史设计与现场记录（多针对已废弃平台，不作现行手册）
- `tmp/` — 本机联调草稿（gitignore，不入库）

## 环境

- .NET 8 SDK；目标机 Windows（FxMonitor 为 WinForms）
