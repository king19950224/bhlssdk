# 螺栓档案生命周期设计:占位与资产两级模型

> 状态:**已实施**(2026-08-17,迁移 0032;生命周期集成测试 4 条 + 既有回归全绿)。
> 触发:探头识别链审查后的两个现场问题——"自动建档后拔掉探头,档案永存"与"探头挪到别的通道,同一颗螺栓出现两份档案"。
> 原则:**做减法**。不新增监测/提示机制,用一个显式的两级模型统一现有全部特例(hold、告警跳过、验收守卫),补齐两条缺失的对称规则。
> 实施落点:`deploy/sql/0032_bolt_confirmed.sql`(列+回填+部分索引)、盖章点 5 处(标定激活
> `MarkBoltCalibratedAsync`、验收 `AcceptanceEndpoints`、改规格 `BoltEndpoints /settings`、绑定迁移

> R3 吸收在 `MoveBoltBindingAsync`(响应带 `absorbedBoltCode`)、UI 占位档"待确认·自动建档"角标
> (`BoltDetail.vue`,API 字段 `confirmedAt`)。

## 0. 问题的本质

系统能自动观测的只有"通道 X 有/无稳定回波"。**回波属于哪颗资产螺栓,物理上永远无法自动确认**(同规格螺栓声时差小于温漂,已划界)。因此:

- "通道↔螺栓"绑定本质是**人工声明的事实**(点位表/验收);
- 自动系统只能做**发现**(哪里有信号)和**守护**(信号还像不像当初声明的);
- 现状的张力:"检测即螺栓"把"发现"直接升级成了"资产声明"——系统替人声明了资产。后续所有补丁(auto_enroll_hold 防复活、ghost 手工清理、迁移前先删占位档)都是在为"自动声明可能是错的"打补丁。

## 1. 两级模型

| 层 | 定义 | 进入方式 | 系统行为 | 退出方式 |
|---|---|---|---|---|
| **占位档**(provisional) | 自动建档且**无人工痕迹**的档案 | auto-enroll(现状) | 采集入库、显示在位;**不出正式预紧力、不评预紧力告警、不进接线守卫**(现状已如此,因未标定/未验收) | ①人工确认 → 升级为资产档;②探头离位满 N 天 → **自动软删**(新增,R2);③人工删除(现状) |
| **资产档**(confirmed) | 被人确认过的档案 | 点位表导入、人工建档、或占位档被人碰过(标定/验收/改规格/迁移) | 完整监测语义 | **只能人工删除**;拔探头 = 失联报警 + 档案永存(现状,不变) |

**判据落地**:`bolts` 加一列 `confirmed_at timestamptz NULL`(唯一的 schema 变更)。

- auto-enroll 建档:`confirmed_at = NULL`;点位表/人工建档:`confirmed_at = now()`;
- 盖章点(各一行 SQL,挂在既有事务里):标定激活、通道验收通过、人工 PATCH 规格/目标/位置、人工 bind/move;
- 占位档 = `confirmed_at IS NULL`。不用"未标定+无目标值"等字段组合推断——auto 档会继承组目标值,推断不可靠。

## 2. 生命周期规则(全部,共 4 条)

| # | 规则 | 现状 | 改动 |
|---|---|---|---|
| R1 | 自动建档 = 发现性占位,不出正式结论 | ✅ 已满足(未标定不出预紧力、无验收不守护) | 仅 UI:占位档加"待确认"角标(查 `confirmed_at IS NULL`) |
| R2 | **对称收回**:占位档探头离位满 N 天(默认 7,可配)自动软删,审计留痕 `system:auto-retire` | ❌ 缺失(ghost 永存) | 新增:挂在每日清理任务里一条 UPDATE(判据 `confirmed_at IS NULL AND last_present_at < now()-N AND hardware_state='no_data'`) |
| R3 | **迁移一步化**:move-channel 的目标通道被**占位档**占用时,同事务自动软删占位档并完成迁移(审计写明"吸收占位档 X");目标是资产档时维持 409 | ❌ 现状要先手工删占位档再迁 | 改一处:move-channel 的 409 分支加条件吸收 |
| R4 | 人工删除在位档案 → `auto_enroll_hold` 防秒级重建,离位清 hold | ✅ 已有 | 不动 |

## 3. 两个现场问题在新模型下的答案

**拔掉探头,档案留存吗?**
资产档:留存 + 失联报警(资产语义,不变)。占位档:没人认领,7 天后自动消失(R2)——误插误建的 ghost 不再需要人记得去删。

**探头挪到别的通道?**
旧通道:资产档失联报警(提醒有人动了现场)。新通道:自动建**占位档**,只采集不声明。运维一步 `move-channel`:占位档被自动吸收、资产档连历史迁过去、标定按策略清除(物理上重新耦合必须重新置零,不变)。原来的三步 SOP(删 ghost → 迁移 → 置零)变成一步 + 置零。

## 4. 明确不做

- **TOF 相似度"疑似挪动"提示**——审查时曾提议,砍掉。迁移低频,R3 一步化后提示价值不足,不为它加一条常驻监测逻辑;
- **探头身份体系**——探头无硬件 ID,物理不可行;
- **任何自动合并/自动迁移**——绑定是人工声明,自动系统不猜。

## 5. 改动量与迁移

| 项 | 量级 |
|---|---|
| SQL 迁移:`bolts.confirmed_at` + 存量回填(有标定记录/验收/人工审计的置 now(),其余 auto 档置 NULL) | 1 个迁移文件 |
| 盖章点 4 处(标定激活/验收/PATCH/bind-move,各 1 行) | 极小 |
| R2 清理规则(挂既有每日清理服务) | ~40 行 + 测试 |
| R3 move-channel 条件吸收 | ~30 行 + 测试 |
| UI 角标 + 占位档列表分区 | 小 |

净效果:概念数量减少(运维不再需要理解"为什么删了会回来 / 为什么迁移前要先删"),代码净增量集中在两条规则上,原有资产语义、hold、守卫、审计全部不动。
