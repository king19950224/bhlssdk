# 厂家软件（iFastApp）与我方系统功能对比

对比日期：2026-08-12。厂家侧样本：`厂家软件/win-x64/`（iFastApp.exe，Avalonia 桌面程序，含内嵌 WebAPI 文档、系统 SQLite 库、Word 报告模板）。这份是厂家自己的调试/试验/监测工位软件，`u_device` 表里躺着 `192.168.0.7:23`——就是在我们现场调过机的那份。

分析材料：`config.json`（功能开关全景）、`Data/sys.db`（数据模型）、`Tpl/`（报告模板体系 + 制作说明）、`webapi.html`（内嵌 OpenAPI 规格，已抠出）、配套两份 1.6 文档。**exe 本体未逆向**，以下结论以随包数据文件为准。

先说定位差异，这决定了怎么读后面的对照表：**厂家软件是单机工位软件**（项目文件制、桌面 UI、一台设备一个工程师），**我们是服务端监测系统**（多设备、多用户、持久化、审计、告警闭环）。两者不是同类产品，"遗失"要按"这个能力对监测系统有没有意义"来判断，不能照单全收。

## 1. 功能对照总表

| 功能域 | 厂家软件 | 我方系统 | 判定 |
|---|---|---|---|
| 设备接入/多通道监测 | 单设备工位（40 通道），meas_freq 10Hz | 多设备 DB 驱动 + 看门狗重连 + WAL 兜底 | 我方强 |
| 扫波/置零/参数配置 | 有（桌面交互） | 有（probe-scan / recalibrate / 配置审批流） | 相当，我方多审批治理 |
| 标定体系 | 材料库理论法 + 试验拟合 | 最小二乘拟合 + 不确定度 + 两人会签 + 过期管理 | 我方强（商用合规向） |
| **材料等级字典** | `u_spec` 20 条（声速/温度系数/声弹系数/弹性模量/屈服强度） | **无**——temp_coefficient 逐通道手填 | **遗失，值得补** |
| 螺栓几何建模 | 公称直径/螺距/中径/夹持长度/材料等级 | nominal_diam/有效长度/截面积（扭矩法用） | 相当，字段口径略不同 |
| **伸长量 elongation** | 对外 API 输出字段 | **无**——只出预紧力 | **遗失，低成本可补** |
| **轮内统计 timeStd** | 每轮 N 次测量聚合出均值+离散度（TimeAvg=16） | **无**——逐帧独立入库 | **遗失，并入信号质量补强** |
| 双波测量 | 报告模板原生支持"单纵波/双波" | 算法层有 GbBiWaveCalculator，采集链未接 EchoTime2/DualMeas | 半缺（能力求证已列 adoption-design 附录#7） |
| 试验模式 | 四类试验报告模板（F/T/TA/TF）+ 总览图/单试验图 | 扭矩阶梯试验（torque_test_points）+ 标定记录 | 部分缺：成型的"试验报告"品类 |
| 报告生成 | **用户自制 Word 模板**引擎（`{{...}}`+动态行列+统计 N/MEAN/STD/MIN/MAX） | 固定格式导出 + 报告签名 | 厂家灵活、我方合规；模板引擎是差异点 |
| **Modbus TCP 从站** | 有（FuncCode 3，DataScale，InvalidData=32768） | **无** | **遗失——风电 SCADA 集成常见硬需求，建议预研** |
| **MQTT / HTTP 推送** | 有（/bolt/{deviceId}/data、wave 双 topic；HTTP 定时 POST） | webhook 通知（告警向）；无测量流推送 | 遗失——看客户集成形态再定 |
| **模拟量输出 AO** | 设备侧 4-20mA 映射（AoConfigs），软件配置 | **无**——SDK 有 `ConfigureAnalogOutputAsync` 未接 | 遗失——有硬件通道（ao_ch），客户要 PLC 直读时接 SDK 即可 |
| 第三方只读 API | 4 个端点（devices/configs/results/warnings）+ 内嵌 swagger | 完整 REST API + Swagger | 我方强 |
| 数据保留策略 | 监测数据/趋势数据分层保留（DataRetentionIndex） | WaveRetention/UnboundRetention/Timescale 压缩 | 相当 |
| 多语言/主题 | LangIndex 多语言、明暗主题、UI 密度 | 中文单语 | 缺——销售需求驱动，暂不做 |
| 项目文件制/自动更新/音效 | 有（桌面软件形态） | 不适用（服务端形态） | 不补 |

**我方独有、厂家软件没有的**（对照时别妄自菲薄）：多用户权限 + license、审计日志（append-only）、告警规则/通知/闭环工作流、通道验收流程、系统健康自监控、WAL 断电兜底、TimescaleDB 时序存储、Web 多端。

## 2. "写错"清单（已核实我方代码）

| # | 位置 | 问题 | 修法 |

| 1 | `web/src/views/BoltDetail.vue:514`、`Diagnostics.vue:217` | 波形图 Y 轴只标"幅值"无单位。SDK 指南 §6.2 明确 WaveData 单位是 mV（厂家软件还带 AdBits=16/AdVolt=10 的换算配置） | Y 轴改"幅值 (mV)"。若发现数值口径像原始 ADC 码而非 mV，先向厂家确认设备输出口径再标 |

## 3. 遗失功能的取舍建议

**第一档：建议补（低成本、监测系统语义下有价值）**

1. **材料等级字典**：建 `material_specs` 表照抄 `u_spec` 结构（name/velocity/temp_coef/acoustic_coef/elastic_modulus/yield_strength），20 条种子数据直接搬。收益：通道温补系数从"手填小数"变"选 10.9/304SS 自动带出"，堵掉填错系数这类低级事故。约 1 人日。
2. **伸长量展示**：纯派生值，预紧力链已有全部输入。公式口径（单程/双程、要不要过声弹系数）向厂家确认后，BoltDetail 加一列即可。半人日。
3. **轮内离散度 timeStd**：厂家按轮聚合（每轮 SingleCount 次）出均值±标准差，我们逐帧入库导致散点全暴露、还没有离散度这个质量指标。**并入 adoption-design §5 的信号质量补强**：不改采集，消费侧按轮/按时间窗算 rolling std，离散度突增=信号劣化预警。与"峰值趋势"同批实现。
4. 写错清单 #1~#3 顺带修。

**第二档：客户需求触发**

- **Modbus TCP 从站**：厂家做了，说明客户群里有 PLC/DCS 直读需求（风电 SCADA 尤其常见）。预研放前（寄存器表设计：轴力/温度/状态按通道排布，InvalidData 哨兵值 32768 的口径可直接对齐厂家，方便客户从厂家软件迁移）。
- MQTT / HTTP 推送：我们 webhook 已覆盖告警面；测量流推送等有集成方要求再做，topic 结构可对齐厂家（`/bolt/{deviceId}/data/report`）降低对接成本。
- AO 模拟量输出：走设备侧（SDK `ConfigureAnalogOutputAsync`），软件只做配置界面。有客户要 4-20mA 再接。
- Word 模板引擎：厂家的 `{{OpenXml...}}` 方案完成度高。我们报告以"合规签名"为主线，模板自由度需求出现再评估（也可以直接兼容厂家模板标记，现场已会做他们的模板）。

**第三档：不补**——项目文件制、多语言、桌面壳、自动更新、提示音；以及厂家的 4 端点只读 API（我们的 REST 全面覆盖）。

## 4. 顺带收获（与功能无关但有用）

- 厂家自己的桌面软件把温度平滑配成 **Fast（60s）**，不是 SDK 默认的 Balanced（180s）——我们选 Direct 的保守取向介于两者之间，方向没毛病；哪天要开平滑，60s 是厂家实践背书的档位。
- `u_device.p_version = V2017`：设备协议版本字段。我们的 devices 表没有此维度，现场设备固件如有代差，排障时记得问这个。
- `u_spec` 的 10.9 钢参数（声速 5890、温度系数 0.00010269）与 SDK 内置默认值完全一致——我们链路里的默认值同源，放心。
- 厂家 config 有 `MaxCalCount 128`（标定点数上限）、`TriggerThrDuration`（触发阈值持续时间）——后者暗示他们有"越限持续 N 秒才报警"的消抖逻辑，与我们告警规则的语义对齐。
