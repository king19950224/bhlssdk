## 1. 根因聚类：四类，不是九个 bug

### R1 抑制/降级状态不可见
系统里存在多个会让数据"不出现"的状态（通道墓碑、删除抑制 hold、设备离线冻结在位、无默认组、
信噪比门拦建档、WAL 降级窗），设计各自成立，但**任何一个被触发，现场看到的都是同一现象：
"我插着探头为什么看不到"**。每次这种困惑 = 一次远程支持工单或上塔排查。
当日闭环：墓碑横幅+恢复、hold 提示+release-enroll-hold 端点、离线横幅、SNR 门提示（已有）。

### R2 推测值冒充事实
位号从编号猜、孔位按数组序回退、规格用缺省 M20/8.8、channel_count 缺失时 COALESCE 回退、
自动法在无信号时锁假过零——推测本身有用，**危险在于推测值获得了只有实测/人工确认才该有的权力**
（扩大盘面、制造冲突、被置零成标定基准）。CH7 假锚定是本类最重后果：假过零被认定为目标预紧力，
若不作废，耦合修复瞬间会折算出 -1.3e7 N 的"松弛"刷 critical。
当日闭环：法兰图两遍落位（标注=主张/推测=填空+标注"推测"）、CH7 锚定作废。

### R3 旧值冒充现状
"最新一行"没有时效门，失联通道的最后读数在法兰外圈、验收报告里当"当前值"。全局时效口径本已存在
（BoltStatusCte 10 分钟 = nodata），但各消费方接入不齐。
当日闭环：法兰外圈守卫、验收报告判定门控。**残余见 §3（告警诊断、报告展示列等 8 处）。**

### R4 内部机制泄漏与维度混用
编号去重 -N、"在线 5/7"分数式、`监测组#1`、`activeChannels/channelCount` 无标签分数、
health.total 当"螺栓数"念——内部实现细节或不同维度的数字混进同一个用户可见表达。
当日闭环：洗名+让位、LivePreload 文案、识别页三维分开统计。**根因（唯一索引含软删行）未动，见 §3。**

## 4. 场景级冲突（08-25 晨间审计，未修，与本研究同源）

这些是"监测逻辑 vs 风电应用场景"层面的问题，本质也是 R2/R3（用假设/滞后的数字做安全判断）：

1. **温补残差量级**：α 用 SDK 默认碳钢值、Pt1000 测端面非声程平均，M20 典型参数下 ≈2.5%/°C——
   12°C 残差即可触发 0.70 告警线；无 |ΔT| 大温差拒测/打标（plan §7.2/§8.4.7 未实现）。
   **动作**：先打标存 ΔT，真机跑完整昼夜做 ratio-温度相关性，反推有效 α，再定动态阈值。
2. **静态阈值抓不住缓慢松弛**（product-design §8.2 自知）：与 1 耦合——季节温漂 ≈7% 与真实松弛同量级，
   趋势告警必须先扣温漂。
3. **全通道轮询稀释采样率**：热插拔是工程态功能，运行态建议收敛"只轮询已建档通道+低频扫空口"。
4. **signal_lost 设备级风暴**：SignalHealthService 不看 connector 离线，整机掉线 = 48 条告警+48 条推送；
   与 ChannelPresenceService.IsDeviceSuspended 口径不一致，应做设备级聚合抑制。
5. **快速换插盲区**：echo_shift（probe-presence-hardening-design 方案 A）待实施；
   人工出口 release-enroll-hold 已于今日落地。

## 5. 防复发工程规则（建议并入 development-guide，评审门槛）

1. **抑制状态三件套**：任何会让通道/螺栓/数据"不出现"的状态，必须同时具备
   ①页面一句话解释 ②一键可逆入口（权限+审计） ③条件满足时的自愈路径。缺一不过评审。
2. **推测值三戒**：推测/回退值 不得扩大物理容器（孔数/通道数）、不得制造冲突或告警、
   必须带"推测"字样上屏；只有人工标注/实测才有物理主张权。
3. **时效门统一**："最新一行"消费必须过 10 分钟全局口径（BoltStatusCte 同款）或明示"最后已知 @时间"；
   API 吐 last\* 字段必须同吐 fresh/status。归档件（报告）双重口径：判定门控 + 展示标注。
4. **命名与计数卫生**：内部计数器/内部 id 不进客户可见字符串；跨维度数字禁止写成 X/Y 分数式，
   必须各自命名（在位 X · 档案 Y · 目录 Z）。
